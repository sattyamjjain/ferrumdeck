### Added

#### Packaging
- **Enforcement engine published to crates.io — importable, not clone-only**: The Rust control-plane crates are now distributable via crates.io under the `ferrumdeck` brand. Because the bare `fd-core` name is already taken on crates.io by an unrelated crate, the packages are renamed at the `[package] name` level — `fd-core → ferrumdeck-core`, `fd-policy → ferrumdeck-policy` — while an explicit `[lib] name` keeps every Rust import path unchanged (`use fd_core::…` / `use fd_policy::…`), so no in-tree code or dependent crate changed beyond adding `package = "…"` to its path dependency. A new thin **`ferrumdeck` umbrella crate** re-exports the enforcement decision path (`pub use fd_policy::*`) so downstream users can `cargo add ferrumdeck` and `use ferrumdeck::{PolicyEngine, ToolAllowlist, …}` with a single dependency; it ships a runnable `examples/enforce.rs`. Full `[package]` metadata (description, `license = Apache-2.0`, repository, homepage, keywords, categories, per-crate README) added to all three published crates; the workspace `repository` URL was corrected to `github.com/sattyamjjain/ferrumdeck`. **Provenance:** a new `.github/workflows/release-crate.yml` (on `v*.*.*` tags or manual dispatch) runs fmt + clippy + tests on the published crates, builds the umbrella example under **`cargo-auditable`** to emit an SBOM-embedded, audit-reviewable binary (`cargo audit bin`) as a provenance artifact, then `cargo publish`es `ferrumdeck-core → ferrumdeck-policy → ferrumdeck` in dependency order using a `CARGO_REGISTRY_TOKEN` secret. README gains an "Install from crates.io" section. Distribution-only — FerrumDeck stays OSS (Apache-2.0); no hosted or paid surface. (Honest scope: `cargo-auditable` embeds the dependency SBOM into *binaries*, not into the source-crate tarball on crates.io — the workflow builds a binary example so audit reviewers get an embedded-SBOM artifact, and downstream binaries built against `ferrumdeck` embed it too.)

#### Performance
- **Reproducible criterion microbenchmark of the enforcement decision path (`rust/crates/fd-policy/benches/enforcement_latency.rs`)**: Measures p50/p95 for the deny-by-default allowlist (`PolicyEngine::evaluate_tool_call_with`), Airlock RASP inspection (`AirlockInspector::inspect`, benign vs. RCE-payload, enforce mode), the R1–R3 reversibility ladder (`graduated_response`), and the EU AI Act Art. 50 transparency rule (`check_art50` + `enforce_art50`). Each case builds its engine/inspector/config **once** outside the timed loop and `black_box`es the inputs; deterministic + offline (no DB, no queue, no network, no LLM). On Apple M4 / `--release` every layer is well under a microsecond at both p50 and p95, summing to ~1 µs for the whole decision stack (allowlist allow ~183 ns, Airlock benign ~437 ns, R3 ladder ~0.54 ns, Art. 50 ~222 ns; 100 samples/case). **Decision-path only — excludes the DB write, the Redis queue hop, and the LLM call, which dominate end-to-end run latency; this is the added CPU cost of the decision, not end-to-end latency, and no "fastest"/"first" claim.** New `scripts/bench-enforcement.sh` + `make bench-enforcement` target (criterion `--save-baseline current` + HTML report path); `criterion = { version = "0.5", features = ["html_reports"] }` dev-dependency + `[[bench]]` target on `fd-policy`. Documented in [`docs/benchmarks/enforcement-latency.md`](docs/benchmarks/enforcement-latency.md) (methodology, hardware/toolchain, full results table, honest scope) and surfaced as a compact "What enforcement costs" table in the README under "Enforce, don't just observe".

#### Evaluation
- **Second benchmark axis — Agent Security Bench (ASB, [arXiv:2410.02644](https://arxiv.org/abs/2410.02644)) + EU AI Act Article 50 transparency-enforcement rule**: A new fd-evals suite (`asb`) alongside the AgentDojo `injection_defense` axis. Where AgentDojo covers *indirect* prompt injection, ASB measures FerrumDeck's **enforcement-plane coverage** against attack classes AgentDojo does **not** — the **Plan-of-Thought (PoT) backdoor**, **memory poisoning**, and **direct prompt injection** — by running a small vendored corpus (`evals/datasets/asb/{governance.json,tasks.jsonl}`, 21 tool-call cases: 13 attacks across `plan_of_thought_backdoor` / `memory_poisoning` / `direct_prompt_injection` / `mixed_attack` / `aggressive_backdoor`, 8 benign controls) through the deny-by-default tool allowlist + Airlock RASP **plus the R1–R3 graduated reversibility ladder** (`fd_policy::reversibility`). The distinguishing case is an *allowlisted-but-irreversible* action (a backdoored `deploy`): the allowlist permits it, Airlock permits it, and the **R3 rung** (`irreversible → require_approval`, not auto-executed) is what stops it — the graduated-enforcement class the allowlist alone would miss. Reports **block-rate-under-attack** and **benign-utility**, each with a **95% Wilson CI** (reusing the `injection_defense` reporter). **Reproduced number: ASB block-rate 100% (13/13), 95% CI [77.2%, 100%]; benign-utility 100% (8/8), 95% CI [67.6%, 100%]** (4 of the 13 attacks stopped specifically by the R3 rung). **Honest framing:** this measures whether the malicious *action* is stopped from auto-executing on a fixed governance profile — **not** backdoor/trigger *detection* and **not** model robustness (no LLM); no first/best claim. **New EU AI Act Article 50 transparency-enforcement rule** (`fd_policy::transparency_art50`, R1–R3-aligned): the enforcement plane requires a generative response to carry a human-readable **AI disclosure** *and* a **machine-readable** synthetic-content marker, and **denies** (enforce, R3 block-before-release) or **logs** (shadow, R1) a response that does not — a structural transparency check (presence of disclosure + marker, not truthfulness/standard-conformance). The suite reports the Art.50 rule alongside the ASB block-rate: **non-compliant responses denied 100% (6/6)**, **compliant preserved 100% (4/4)** over `evals/datasets/asb/art50_cases.jsonl`. **Honesty anchor:** the corpus is pinned to the **real Rust enforcement** by `rust/crates/fd-policy/tests/asb_defense.rs`, which runs the actual `ToolAllowlist` + `AirlockInspector` + reversibility ladder over every tool-call case (and asserts the R3 rung is the decisive layer for the PoT class) and the real `transparency_art50` rule over every response case, failing if any decision drifts; the Python `fd_evals.asb` mirror must agree with the same corpus (cross-plane parity, seeded/order-independent). New `fd_evals.asb` module, a `fd-eval asb` CLI subcommand (`--suite asb --seed 0`, gates on the CI lower bound + corpus parity, writes `evals/reports/asb-<date>.{json,md}`), `evals/suites/asb/suite.yaml`, and a `make eval-asb` target. Tests: 2 Rust integration tests (real-enforcement corpus pin: ASB block-rate + R3-decisive assertion; Art.50 rule) + 13 new Rust unit tests for `transparency_art50` + 22 new Python tests (parity, per-attack-type block, reversibility-ladder decision, Art.50 enforce/shadow, seed-invariance). No-pivot guardrails intact: dual-plane split, MCP-as-tool-protocol, OTel/Jaeger GenAI semconv all unchanged; no SaaS/pricing.
- **Reproducible AgentDojo-style injection-defense block-rate suite (`injection_defense`)**: A new fd-evals suite that measures FerrumDeck's **defense-path coverage** against indirect prompt injection — deterministic, **offline, no LLM** (it exercises the policy/RASP layer, not model quality). #### Reliability
- **Claim grounding rate — grounding rate _per VeriGraph_ ([arXiv:2606.16603](https://arxiv.org/abs/2606.16603))**: A per-run reliability metric (`0.0–1.0`) — the fraction of the final agent output's claims that are **reachable from a tool-output source node** via the run's evidence graph, per VeriGraph's claim-level grounding definition. A *lineage* to the claim-level auditability literature, **not** a ferrumdeck-original metric. New `fd_otel::claim_grounding` (Rust) computes it at the gateway run-completion choke point from the final `output` + the run's tool-step outputs; mirrored by `fd_evals.claim_grounding` (Python) for the eval plane (additive-optional `EvalResult.claim_grounding`), with a **shared golden fixture** (`fd-evals/tests/fixtures/claim_grounding.golden.json`) asserted by both a Rust and a Python test to pin cross-plane agreement. **Honest scope:** the "reachable evidence path" is a **deterministic lexical-overlap reachability proxy** (sentence-split claims; a claim is grounded when ≥ 50% of its significant tokens are covered by a source node) — pure, CI-stable, **no LLM judge** — in the same spirit as the tool-call firing rate. **Persisted** on the run row (`runs.claim_grounding_rate REAL` + `runs.claim_grounding_flagged BOOLEAN`, additive migration) next to cost/tokens and returned on the polled `GET /v1/runs/{id}` → `RunResponse`; **emitted** on the run-completion span (`ferrumdeck.reliability.claim_grounding_rate` + `_below_threshold` + `_threshold`, new `fd_otel::genai::attrs` keys mirrored in `fd_runtime.tracing`); **surfaced** as a "Grounding" stat card on the run console next to Cost (null-for-legacy). **Optional flagging gate, OFF by default:** a project may set `min_claim_grounding_rate` in its `projects.settings` JSONB to *flag* a run below it (`claim_grounding_flagged` + a `reliability.claim_grounding_below_threshold` audit signal + an amber badge) — it **never** blocks a tool or kills a run, preserving the deny-by-default posture for *tool permissions*, not reliability scoring. The existing cost/policy gates are untouched. Tests: 9 new Rust unit tests + 10 new Python tests (incl. the cross-plane golden parity) + 3 new jest tests for the card. See [`docs/runbooks/claim-grounding-rate.md`](docs/runbooks/claim-grounding-rate.md).

#### Governance
- **Reversibility-aware graduated response — DeepMind AI Control Roadmap R1–R3 ladder**: A `Reversibility { reversible, costly, irreversible }` dimension on the tool registry, **orthogonal** to the existing `risk_level` tiers (which are untouched), drives a graduated response in the policy engine. New `fd_policy::reversibility` maps reversibility (+ the run's budget headroom) onto a `ResponseLevel`: `reversible` → **R1** `allow_and_log` (monitor, no gate); `costly` → **R2** `allow_under_budget` while the run's cost budget has headroom, escalating to **R3** when exhausted; `irreversible` → **R3** `require_approval` (the existing human-in-the-loop gate). Deny-by-default: an unregistered tool defaults to `irreversible`. The rung is folded into the allowlist decision **more-restrictive-wins** (`combine`, ranked like the crate precedence `Deny > RequiresApproval > Allow`) — it can only *add* friction, never loosen a `Deny` or an existing approval requirement. Wired end-to-end through `gateway::check_tool_policy`: the tool's reversibility is looked up from the registry (unknown → irreversible), the budget-headroom predicate is the new `Budget::has_cost_headroom`, and the chosen rung is **emitted on the existing OTel/GenAI span** (`ferrumdeck.policy.response_level` + `ferrumdeck.policy.reversibility`, new `fd_otel::genai::attrs` keys), the **immutable audit log** (`reversibility` / `response_level` / `response_rung` / `effective_decision` / `budget_headroom` in the policy audit details), the `check-tool` response (`reversibility` + `response_level`), and **persisted on the run** (`runs.response_level`, surfaced on the polled `GET /v1/runs/{id}` → `RunResponse`). Storage: new `tools.reversibility` (TEXT, default `irreversible`) + `runs.response_level` (TEXT) columns via an additive migration; `CreateToolRequest` accepts an optional `reversibility`. Dashboard: a new `ResponseLevelBadge` (R1/R2/R3, green/amber/red) on the run header, reading the polled run endpoint; a `policy.response.recorded` SSE wire shape is defined for parity with the gateway→BFF push **deferred** (same pattern as `run.forecast.updated`). Tests: 12 new Rust unit tests (ladder, budget-headroom, combine-never-loosens, serde) + 6 deterministic CI-gating Python eval tests (`tests/test_reversibility_gate.py`: reversible passes without a gate, irreversible blocks until approval, costly flips to approval on budget breach) mirroring the Rust contract + 4 new jest tests for the badge. See [`docs/runbooks/graduated-response-levels.md`](docs/runbooks/graduated-response-levels.md). Design reference: DeepMind, *An Approach to Technical AGI Safety* (AI Control Roadmap R1–R3).

#### Safety
- **Coherence-divergence — graduated R1–R3 enforcement + SSE + drift demo ([arXiv:2606.07889](https://arxiv.org/abs/2606.07889))**: Turns the live coherence signal into a *graduated enforcement* action, completing the enforce-not-observe wedge. A detected divergence now maps onto the existing reversibility ladder via the new `CoherenceSpan::response_level` (reusing `fd_policy::reversibility::ResponseLevel`, **not** a new shape): severity → rung, `Critical`/`High` → **R3** `require_approval`, `Medium` → **R2** `allow_under_budget`, `Low` → **R1** `allow_and_log` (default `risk_score` 70 → High → R3). Two modes mirror the Airlock shadow/enforce convention, held on `AppState`: **`shadow` (default)** records + surfaces the rung (audit `details.response_level`/`response_rung`/`mode`/`gated`, the run's `response_level`, the SSE event) but never gates; **`enforce`** (`FERRUMDECK_COHERENCE_MODE=enforce`) gates an **R3** divergence — the run is set to `WaitingApproval` for human review instead of `Completed` (the `run.completed` audit is suppressed when gated). The rung rides the **same** `airlock.violation_detected` audit path (no new store); `details.blocked` now equals `gated`. New **`coherence.divergence.detected` SSE event** on the run stream carrying the category, confidence, `response_level`/`response_rung`, `gated`, and the stated-fact / contradicting-action quotes (TS `CoherenceDivergenceDetectedPayload`); the gateway logs the structured event shape and the BFF mock generator locks the wire shape, gateway→BFF push deferred (same pattern as `run.forecast.updated` / `routing.decision.recorded`). New **one-command drift demo** `examples/demo/coherence-drift.py` (section 8 of `run-demo.sh`): a pure, no-stack, self-verifying proof that a deliberately drifting run (states "tests failing"/"permission denied", then commits/deploys) is caught + R-tiered and a coherent control is not — its real output is in the README "What this proves". The Python mirror `fd_evals.coherence` gains the parity mapping (`response_level_for_score`/`response_rung`/`risk_level_for_score` + `CoherenceSpan.response_level`). Tests: +1 Rust unit (`response_level_maps_severity_to_r_tier`), +1 Rust gateway integration (`enforce_mode_gates_r3_divergence`), the drift demo self-check. See [`docs/runbooks/coherence-divergence.md`](docs/runbooks/coherence-divergence.md).
- **Coherence-divergence monitor — wired live at the gateway run stream ([arXiv:2606.07889](https://arxiv.org/abs/2606.07889))**: The `CoherenceMonitor` (previously a library primitive) is now fed by the live run-trajectory stream, so it fires **during** a run rather than only in offline tests. A process-wide monitor is held on `AppState` (keyed per run internally); `gateway::submit_step_result` projects each submitted step into trajectory events via `step_trajectory_events` — a Tool step becomes an advancing **action** (the invocation) followed by a **statement** (its observed output/error); a reasoning step contributes statements only — and feeds them to `CoherenceMonitor::observe_event`. The instant a divergence completes, it surfaces mid-run through the **same** `airlock.violation_detected` `audit_events` path every other Airlock layer uses (`details.violation_type = coherence_divergence`, the full `CoherenceSpan` under `details.coherence`, `details.blocked = false`) — no parallel store, no parallel decision channel. At run completion a synthetic "reports success" closure action (carrying the final output, so an honest disclaimer suppresses it) is fed, so a run that terminates with an unresolved blocking fact also flags. **Reliability signal, never a gate**, mirroring claim-grounding: it never blocks a tool or changes run status. **Persisted** on the run row (`runs.coherence_divergence_flagged BOOLEAN`, nullable → null-for-legacy; additive migration) and returned on `GET /v1/runs/{id}` → `RunResponse`; **emitted** on the run-completion span (`ferrumdeck.reliability.coherence_divergence`, new `fd_otel::genai::attrs` key mirrored in `fd_runtime.tracing`); **surfaced** as a "Coherence" stat card on the run console next to Grounding (amber "Divergent" / green "Coherent", null-for-legacy). Terminal branches (`Completed` / `BudgetKilled` / `Failed`) call `clear_run` to free per-run state. Enabled by default; toggle with `FERRUMDECK_COHERENCE_ENABLED=false`. Cross-plane parity: a new Python eval-plane mirror `fd_evals.coherence` (a verbatim port of the detection core) replays a trajectory offline, and a **shared golden fixture** (`fd-evals/tests/fixtures/coherence_divergence.golden.json`) is asserted by both a Rust `golden_fixture_matches_python` test and the Python `TestGoldenParity` test to pin that the planes classify an identical trajectory identically. **Known limitation:** the per-run trajectory window lives in gateway memory, so a multi-instance deployment tracks each run only within the instance that receives its steps (the completion-time synthetic closure still flags the common "reports success despite an in-step blocker" case). Tests: 2 new Rust gateway integration tests (`coherence_live_consumer`: a divergent trajectory through the live consumer produces an `audit_events` record with `violation_type = coherence_divergence`; a coherent one produces none) + the Rust golden parity test + 8 new Python tests (detection core + shared-golden parity) + 3 new jest tests for the card. See [`docs/runbooks/coherence-divergence.md`](docs/runbooks/coherence-divergence.md).
- **Coherence-divergence monitor ([arXiv:2606.07889](https://arxiv.org/abs/2606.07889))**: A new trajectory-level Airlock RASP signal in `fd_policy::airlock::coherence`. Every existing Airlock layer inspects a *single* tool call in isolation; this monitor instead consumes the agent run **trajectory** — the existing audit-trail event stream — and flags a *sequential* failure no per-call check can see: the agent **states a fact that should change its plan** ("tests still failing", "permission denied", "the file does not exist") and the very next *advancing* action proceeds **as if that fact were untrue** (marks the task done, commits, reports success). Anchored on *Strained Coherence* — in that study, trajectories exhibiting this divergence failed **94%** of the time vs **46%** without it (Fisher's exact p = 0.003), a pre-failure signal worth surfacing *before* the run finishes. The monitor is therefore **streaming**: `CoherenceMonitor::observe_event` consumes one trajectory event at a time and returns a `CoherenceSpan` the instant a divergence appears (not only in a post-hoc autopsy); a stateless `CoherenceMonitor::scan_trajectory` replays a whole slice for tests / offline analysis, sharing the exact same detection core. Each `CoherenceSpan` carries the **stated-fact quote**, the **contradicting action**, a **confidence** in `[0, 1]`, a **severity** (reuses the Airlock `RiskLevel`), the event gap, and the `arxiv:2606.07889` anchor. **Diff-compatible with the audit schema**: `CoherenceSpan::to_violation()` projects onto the shared `AirlockViolation` shape (`violation_type = coherence_divergence`, span JSON in `details`, `trigger = coherence_divergence:<category>`), so a divergence flows through the identical `audit_events.details` path as every other Airlock layer — no parallel store, no parallel decision channel. A false-positive guard keeps it honest: a run that **acknowledges and acts on** the blocking fact — remediates, states it resolved (per-category or generic), or disclaims success in the action itself ("cannot mark complete, permission denied") — does not fire; a configurable `min_confidence` floor and a `lookahead` staleness window bound spurious pairings. Blocking facts are bucketed into five categories (`test_failure`, `permission_denied`, `missing_resource`, `build_error`, `generic_error`) driving severity and resolution matching. Driven by its own `CoherenceConfig` (separate from the per-call `AirlockConfig`, since it runs via `CoherenceMonitor` rather than `AirlockInspector::inspect`). New `ViolationType::CoherenceDivergence` variant; re-exported from the crate root as `CoherenceMonitor`, `CoherenceConfig`, `CoherenceSpan`, `TrajectoryEvent`, `BlockingCategory`, `COHERENCE_ANCHOR`. 16 new Rust unit tests cover synthetic trajectories: divergence fires (tests-failing → mark-complete; permission-denied → commit; missing-file → report-success across a gap), coherent runs do **not** fire (acknowledge+remediate+resolve, disclaiming action, clean run with no blocker, remediation-is-not-closure, generic resolution), plus the staleness window, the `min_confidence` gate, the disabled short-circuit, streaming-emission timing (`observe_event` returns `None` on the stated fact and `Some` exactly on the contradicting action), `clear_run`, quote clipping, the `to_violation` round-trip, and multiple divergences in one trajectory. **Status: wired live at the gateway run stream** (see the follow-up entry below). See the README "Coherence-Divergence Monitor" subsection and [`docs/runbooks/coherence-divergence.md`](docs/runbooks/coherence-divergence.md).

#### Governance
- **Eval-driven harness suggestions — trace→delta (HarnessX)**: Turns fd-evals from a pass/fail gate into a closed trace→signal loop without touching the dual-plane split or the deny-by-default posture. fd-evals derives a *proposed* harness/policy delta from the aggregate signal across an eval run's trace (new `fd_evals.harness_delta`: `derive_harness_deltas(summaries, config)` — v1 rules are budget-breach-rate → tighter per-run cap, and low aggregate pass rate → require approval, both computed only from fields already on `EvalRunSummary`) and POSTs it to the control plane. - **Receiver attestation for self-reported spans (optional, off by default)**: FerrumDeck tool/service spans are agent-self-reported. #### Governance
- **Delegation-aware budget leases ([arXiv:2606.04056](https://arxiv.org/abs/2606.04056))**: The existing `BudgetUsage::check_against` gate is stateless — it compares an accumulated usage snapshot against a `Budget` cap. That is correct for a single linear run but has a known failure mode under **delegation fan-out** (the Token-Budgets delegation class): when a parent delegates to N children and each child checks its own spend against the *same* parent cap, the children can collectively spend up to `N ×` the cap because every child believes it owns the whole budget. New `fd_policy::lease` primitive closes the gap without touching `check_against` (purely additive). All leases descended from one root share a single atomic remaining-budget pool (`SharedBudget`, one `Arc<AtomicU64>`) — the one source of truth for the entire delegation tree. `BudgetLease::delegate(amount)` hands a child a sub-lease **carved from** the parent's authority (the `amount` is moved *out of* the parent's cap, not copied alongside it, so authority is conserved), and `BudgetLease::spend` decrements the single shared pool via an atomic all-or-nothing reservation (`fetch_update` with `checked_sub`, lock-free, floors at zero). Total spend across parent + all children therefore can never exceed the root cap, regardless of fan-out width or concurrency. `subordinate()` models the worst-case fan-out the paper warns about — a child handed authority up to the *full* remaining budget — done safely, since it still shares the one pool. **Move semantics enforce single-ownership of authority**: `BudgetLease` is intentionally `!Copy` and `!Clone`, so a lease moved into a delegated child cannot also be spent by the parent — a compile error (a `compile_fail` doctest pins use-after-`close`), with `LeaseError::Inactive` backstopping the cases the borrow checker cannot see at runtime. 12 new Rust unit tests, including the paper's experiment: a 1-parent→3-children fan-out under concurrent spend (each child hammering 1 unit at a time against an over-allocated cap) spends *exactly* the root cap — **0/N overshoot** — while the naive copied-counter baseline (each child gets its own private counter) overshoots to `N ×` the cap; the test asserts both the exact lease total and `lease_total < baseline_total` to document the failure mode the shared pool eliminates. Re-exported from the crate root as `BudgetLease`, `SharedBudget`, `LeaseError`, `LEASE_ANCHOR`.
- **Champion-challenger promotion gate**: A registered model / prompt / tool **version** (the challenger) cannot replace the live version (the champion) until it clears a deterministic gate — configurable metric thresholds (inclusive floors) **plus** a required human approval. Deny-by-default: a freshly registered version stays in `shadow` and serves no traffic until explicitly promoted. New `fd_policy::promotion` primitive emits its verdict through the **same** `PolicyDecision` channel every other gate uses (`Deny` below threshold, `RequiresApproval` when thresholds clear but approval is absent, `Allow` when both are satisfied) — a new *rule source*, not a parallel decision channel.
