# Governed vs ungoverned — reproducible results

**Artifact version:** FerrumDeck 0.7.11 · **Run date:** 2026-07-26 · **Machine-independent
figures only** (latency is reported separately as an order of magnitude, not pinned).

FerrumDeck's governance layer, measured on **recognized, citable workloads** and run
two ways — **ungoverned** (no decision point, the honest model of a record-only /
observability-only stack) vs **governed** (the deny-by-default allowlist + Airlock
RASP + spend gate, deciding *before* execution). Every number below is regenerated by
the reproduce commands in the last section and is **pinned to the real Rust
`fd_policy` engine** by the cited `cargo test` targets — the Python harness mirrors the
engine and cannot drift from it without failing those tests.

## Workloads

| Workload | Source (citable) | Version | Cases |
|---|---|---|---|
| Indirect-prompt-injection corpus | AgentDojo-style attack/benign split ([arXiv:2406.13352](https://arxiv.org/abs/2406.13352)) | v1 (`evals/datasets/injection_defense`) | 25 (17 attack / 8 benign) |
| Safe-PR-agent trajectory | FerrumDeck governed-benchmark (fixed) | v1 (`evals/datasets/governed_benchmark`) | 13 steps, 4 injected unsafe |
| AP2 payment mandates | Google AP2 signed Intent+Cart mandates | v1 (`ap2_mandates.jsonl`) | 4 (1 valid / 3 unsafe) |

No LLM is involved: these exercise the **policy / RASP / spend-gate layer**,
deterministically and offline. "Ungoverned ASR = 100%" is the honest model of a stack
with no decision point — the attack tool-action reaches execution because nothing
stops it.

## Headline

### 1. Indirect-prompt-injection (AgentDojo-style, arXiv:2406.13352)

| Metric | Ungoverned | Governed | 95% CI (Wilson) |
|---|---|---|---|
| **Attack success rate (ASR)** | **100.0%** (17/17 reach execution) | **0.0%** (0/17) | block-rate CI [81.6%, 100.0%] |
| **Attacks blocked** | 0/17 | **17/17 (100%)** | — |
| **Benign-task utility retained** | 100% (8/8) | **100% (8/8)** | CI [67.6%, 100.0%] |

Block-rate by attack type: `unauthorized_tool` 6/6 · `rce_payload` 6/6 ·
`exfil_domain` 5/5. **Utility retained 100%** — the gate blocked every attack while
letting every benign task through (0 false-positives on this corpus).

### 2. Spend-overrun on a governed agent trajectory

| Metric | Ungoverned | Governed |
|---|---|---|
| **Unsafe tool actions blocked** | 0/4 (0%) | **4/4 (100%)** — RCE write, raw-IP exfil, denied tool, over-budget loop |
| **Run spend** | 184.0¢ | **85.36¢** (net **−98.64¢**, ≈54% less) |

The governed run costs **less**, not more: stopping the RCE, the exfil, the denied
tool, and the runaway over-budget loop saves far more than the per-decision audit
overhead (+0.36¢ / +720 tokens over 18 decisions).

### 3. Payment-governance scenario (the mandate an agent tries to overspend)

The explicit "an agent overspends an AP2 mandate / an x402 call → the gate blocks,
audit-logged" case, run through the real `fd-policy` `x402.rs` / `ap2.rs` / `budget.rs`
path:

| Metric | Ungoverned | Governed |
|---|---|---|
| **Unsafe payment mandates blocked** | 0/3 (0%) | **3/3 (100%)** |
| **Payments authorized** | 4/4 (all) | **1/4** (only the valid, in-scope, in-budget cart) |
| **Payment spend** | **$150.95** | **$0.40** |

The three blocked mandates fail on distinct controls — **invalid Ed25519 signature**
(tampered cart total), **cart over the per-task budget ceiling** ($150 vs the $1.00
ceiling), and **merchant outside the signed intent scope** — each a hard `deny` mapped
to a `PolicyDecision::deny`. Every decision is **audit-logged**: it emits a
`ferrumdeck.decision` GenAI span with a W3C `traceparent` (MCP SEP-414) and an
append-only audit record, so the block is queryable after the fact, not just enforced.
The x402 rail enforces the same ceiling for inline HTTP-402 quotes.

## Reproduce

Deterministic and offline (no API key, no network, no LLM):

```bash
# 1. Injection ASR + benign utility (AgentDojo-style corpus)
uv run python -m fd_evals injection-defense        # or: make eval-injection-defense

# 2. Governed-vs-ungoverned spend + the AP2 payment rail
make bench-governed                                # fd-eval governed-benchmark

# 3. The record-only vs in-path-gate contrast on one public injection trace
make bench-enforce-vs-observe

# 4. Pin every number to the REAL Rust engine (not the Python mirror)
cargo test -p ferrumdeck-policy --test injection_defense   # anti-RCE + exfil + allowlist
cargo test -p ferrumdeck-policy --test governed_benchmark  # spend + block-set
cargo test -p ferrumdeck-policy --test ap2_gate            # real Ed25519 mandate gate
```

## Honest caveats

- **Layer, not model.** This measures the enforcement layer (policy + RASP + spend
  gate), not LLM robustness. "ASR" here is *"the attack tool-action reached
  execution,"* a narrower, deterministic claim than end-to-end task compromise — but
  it is exactly the layer FerrumDeck governs. A model that never emits the unsafe call
  is a different (and complementary) line of defense.
- **Small N, wide intervals.** 17 attacks / 8 benign is a compact corpus; the Wilson
  intervals are reported precisely because 100% on small N still has a real lower bound
  (block-rate floor 81.6%, utility floor 67.6%). The numbers are a **reproducible
  contrast**, not a leaderboard score.
- **Pinned, not re-implemented.** The Python decision mirrors the Rust `fd_policy`
  contract and is pinned to it by the `cargo test` targets above; if the engine and
  the mirror ever diverge, those tests fail. The AP2 lane models the verified state of
  the signature chain (`signature_valid` / `in_scope`); the **cryptography itself** is
  proven on the Rust plane by `ap2_gate.rs` (real Ed25519 sign+verify).
- **Ungoverned = record-only.** The ungoverned lane is the honest model of an
  observability-only stack (OTel / Langfuse-style): it *records* the call but has no
  decision point to stop it. It is not a strawman — it is what "just add tracing" gets
  you.
- **Deterministic ≠ exhaustive.** Fixed corpora make the artifact reproducible; they do
  not enumerate every attack. New attack classes require new corpus cases (the corpus
  is versioned so additions are visible).
- **Not a compliance certification.** The standards alignment is a mapping to advisory
  guidance and an enforcement-date tie-in, not an audit or a legal opinion.
